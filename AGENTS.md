# Project language

- Use English for project-authored documentation, user-facing text, comments, docstrings, test descriptions and new identifiers.
- Keep documentation links and heading anchors consistent when editing text.
- Preserve source quotations, dataset values and input-recognition aliases exactly. These are evidence or parsing data, not interface copy; translating them can change validation behavior.

# Documentation style

- Keep product documentation concise and factual. Describe behavior, setup and measured results.
- Do not include personal handoffs, owner-review tasks, publication checklists or generation instructions in public documentation.
- Preserve measured limitations and known errors; do not replace them with unsupported quality claims.
